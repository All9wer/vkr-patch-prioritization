# Приоритизация патч-менеджмента
Тема: «Разработка рекомендательной системы приоритизации патч-менеджмента».

## О чём работа

Уязвимостей находят больше, чем успевают закрыть, поэтому приходится выбирать, что закрывать первым. Обычно выбирают по CVSS. Но CVSS оценивает опасность уязвимости "в целом" и не знает, атакуют ли её на самом деле и где она стоит в инфраструктуре. В итоге много сил уходит на уязвимости, которые никто не атакует.

Цель работы: сделать способ приоритизации, который учитывает реальную эксплуатацию и контекст инфраструктуры и поэтому находит опасные уязвимости при меньшем объёме работ.

## Как проверяю

На прошлых данных. Беру дату в прошлом (например, 1 января 2022), уязвимости, опубликованные за год до неё, и сортирую их разными способами. Потом смотрю по каталогу CISA KEV, какие из них реально начали атаковать в следующем году, и какой способ поставил их ближе к началу очереди.

## Что уже есть

- скачивание данных: CISA KEV, NVD, EPSS
- срезы на четыре даты за 2022-2023 годы
- сравнение базовых способов: случайный порядок, CVSS, EPSS
- отчёт с таблицами и графиком

вывод: чтобы закрыть 80% реально атакуемых уязвимостей, при сортировке по CVSS надо закрыть больше половины всех. EPSS сильно лучше CVSS в начале очереди, но для 80% тоже требует примерно половину. Это и есть планка для моей модели.

## Как запустить

Нужен Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

patchprio fetch      # скачать данные
patchprio baseline   # посчитать и построить отчёт в experiments/results/
pytest               # тесты
```

## Структура

```
config/             настройки эксперимента
docs/               методика и план ВКР
src/patchprio/
  collectors/       скачивание и чтение данных
  dataset.py        срез на дату в прошлом
  ranking/          способы сортировки
  evaluation/       метрики, эксперимент, отчёт
  context/          описание актива (для стенда)
  llm/              заготовка под языковые модели
tests/              тесты
```
